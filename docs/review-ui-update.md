# Review the 0.6.5 UI update

This update adds Classic and Neobrutalism appearances, reorganizes the popup into two tabs, and preserves existing users' settings. Review the behavior and ownership before the visual tokens and generated assets.

For the focused settings synchronization repair, use [Review settings ownership](review-settings-owner.md). Its task patch compares against the existing uncommitted UI work.

## Start with the behavior

| Situation | Appearance |
| --- | --- |
| Existing installation updating without a prior appearance choice | Classic |
| New installation | Neobrutalism |
| Existing explicit choice | Preserve the choice |
| Legacy backup without an appearance field | Classic |

Brightness remains a separate `theme` preference. Updating does not enable subtitle navigation, request caption permissions, or add an appearance announcement.

## Follow the owners

1. Read `src/shared/ui-styles.ts`, the `uiStyle` field in `shortcut-types.ts`, and normalization in `shortcut-settings.ts`. The registry defines valid styles; settings version 13 adds the preference. `settings-backup.ts` validates and restores it.
2. Read `src/shared/storage.ts` and `src/background/settings-migration.ts`. Storage owns functional settings, the independent appearance selection, and installation defaults. The background classifies install versus update. [Verify settings upgrades](settings-upgrade.md) describes precedence and recovery.
3. Read `src/popup/popup-app.tsx`. It owns the form, activation, compatibility session, navigation, and disclosure lifetime. `popup-shortcuts-panel.tsx` and `popup-settings-panel.tsx` render controlled tab content. They do not create another form or permission workflow.
4. Read `src/shared/use-shortcut-settings-form.ts` and `src/shared/use-subtitle-activation.ts` when reviewing a mutation. The form owns drafts and optimistic save feedback; storage owns write ordering and freshness. Activation owns permission attempts and cancellation. Options and popup use these same owners.
5. Read `src/styles/themes/*.css` and the affected `src/components/app-ui` adapters. The same component tree consumes both sets of theme tokens. `components/ui` remains upstream registry code.

## Check the contracts that can break

- Every functional storage event reaches subscribers synchronously, including a rapid global off/on pair. Late hydration cannot restore stale values.
- A known empty storage result differs from an unhydrated subscription. Appearance-only changes must still notify an empty installation.
- Bootstrap writes defaults without overwriting the explicit selection or functional object. It records local recovery information before the sync write.
- Form and disclosure state remain above the tab panels. Switching tabs saves a focused numeric input before Radix unmounts it.
- Permission requests start from the user's gesture. Disabling the extension or closing the view invalidates a pending attempt.
- Selected tabs keep their colors on hover. Unselected tabs retain hover feedback.

The existing popup, storage-upgrade, subtitle-activation sync, and appearance-sync tests exercise these contracts. Keep those integration tests intact when reorganizing components.

## Review mechanical files separately

`public/icons/icon-classic*.png` is generated from the source images in `assets/icons` by `scripts/generate-icons.ts`. `package.json` and the root lockfile entries move together to 0.6.5. Build verification compares both generated manifest versions with the package version. These files do not define appearance selection or migration policy.

The v0.6.4 JSON fixture is generated by that release's settings and backup implementations. Review its source commit and behavioral assertions rather than treating the repeated fixture data as new runtime logic.

Automated checks and the local popup preview do not prove installed-browser update delivery or real cross-device sync. The installed-update checklist is in [Verify settings upgrades](settings-upgrade.md).
